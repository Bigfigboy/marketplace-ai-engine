# Architecture

## Обзор

```
Marketplace frontend ──► Marketplace backend ──(JWT / API key)──► AI Engine (FastAPI)
                                                                     │
          ┌──────────────────────────────────────────────────────────┼─────────────────────┐
          │ CORS → RequestContext (request id, headers, body size) → Auth + rate limit      │
          │                                   │                                              │
          │  /agents/{slug}/run ─► runner: options → language → files (ACL) → quotas         │
          │                        → guardrails → agent.precheck → agent.run → cost → log    │
          │                                   │                                              │
          │   AgentRegistry ── marketing │ support │ hr  (BaseAgent)                         │
          │                                   │                                              │
          │   LLM provider: OpenAIProvider (timeouts, bounded retries) │ MockProvider        │
          │   Services: extraction, RAG (BM25), hr_tools, quotas, pricing, stats             │
          └──────────────┬─────────────────────────────┬────────────────────────────────────┘
                         │                             │
                  SQLite / PostgreSQL           Private file storage
            (companies, users, api_keys,      STORAGE_DIR/<company_id>/<file_id>.bin|.txt
             files, document_chunks,
             agent_runs)
```

## Стандарт агента

`app/agents/base.py::BaseAgent` — единый контракт: `id`, `slug`, `name`, `description`, `version`,
`category`, `supported_languages`, `capabilities`, `options_model` (→ `input_schema`),
`output_model` (→ `output_schema`), `accepted_file_purposes`, `max_files`, `precheck()`, `run()`.

Агент получает `AgentContext`: язык, уже проверенные по ACL файлы, историю, `call_llm()` (учёт
токенов, лимиты входа/выхода, дедлайн), БД-сессию для своих запросов (support фильтрует по
`company_id`). Агент не видит HTTP-запрос, заголовки и данные других компаний.

`AgentRegistry` загружает модули из `AGENT_MODULES`, только из пакета `app.agents.*`.
Новый агент = новый модуль + строка в конфиге; API не меняется (проверено тестом
`test_new_agent_plugs_into_registry_without_api_changes`).

### Масштабирование до сотен агентов

- Каталог/метаданные — из `GET /agents`; маркетплейс хранит цены и подписки у себя.
- Агенты от сторонних разработчиков **не исполняются** внутри движка. Путь развития:
  (1) декларативные агенты (промпт + схема опций + разрешённые типы файлов в БД) с исполнением
  тем же runner'ом — без стороннего кода; (2) сторонний код — как отдельные сервисы в изолированной
  среде с HTTP-контрактом `RunRequest → RunResponse`, вызываемые через «remote agent» адаптер,
  с ревью, подписью образов и лимитами.
- Горизонтально: несколько реплик за балансировщиком + PostgreSQL + Redis для rate limit +
  объектное хранилище для файлов; тяжёлые запросы — через очередь (Celery/RQ) с polling по `run_id`.

## Агенты

### Marketing (`marketing`)
Определение задачи (8 типов) по ключевым словам ru/kk/en или `options.task`; платформы. Бриф из
опций и прикреплённые файлы передаются как недоверенные данные. Промпт: контекст Казахстана
(тенге, двуязычный рынок, локальные каналы, праздники), запрет на выдуманную статистику/цены/
конкурентов (плейсхолдеры `[укажите данные]`), только черновики. Ответ — Markdown + пометка
«черновик»; предупреждение, если в тексте есть проценты/миллионы.

### Support (`support`)
1. Загрузка: текст → фрагменты ~900 символов с перекрытием → `document_chunks` с `company_id`;
   фрагменты с подозрительными инструкциями помечаются.
2. Запрос: BM25 (префиксный стемминг, стоп-слова ru/kk/en) **только по фрагментам компании**
   вызывающего; порог релевантности. Нет базы / нет релевантных фрагментов →
   `escalation_required` **без вызова LLM** (экономия, нет галлюцинаций).
3. Фрагменты очищаются от инструкций, нумеруются `S1..Sn`, оборачиваются в
   `<untrusted_knowledge_base>`; модель отвечает JSON (`status`, `intent`, `answer`, `source_ids`, `handoff`).
4. Серверная проверка: `source_ids` только из выданных; ответ без валидных источников →
   эскалация; фразы «передано менеджеру / менеджер свяжется» удаляются; `handoff.delivered = false`.

### HR (`hr`)
- `precheck`: отказ без вызова LLM на запросы ранжирования, решений о найме/отказе, оценок,
  учёта защищённых характеристик (с исключением формулировок «без указания возраста…») — проверяются
  сообщение, вся история диалога, `job_title` и `job_description`.
- Маскирование ПДн применяется ко всем текстам (резюме и вакансии); файл `job_description`, похожий на
  резюме, отклоняется (`job_description_looks_like_resume`).
- Максимум одно резюме за запуск (невозможно сравнивать кандидатов).
- Перед отправкой в LLM маскируются: ФИО (эвристика), email, телефоны, ссылки, ИИН, строки
  «дата рождения / пол / национальность / семейное положение / дети / религия…» (ru/kk/en).
- Ответ модели (JSON) очищается от полей `score/rank/fit/recommendation/decision/age/gender/...` и
  фраз-решений; навык/требование считается «подтверждённым», только если цитата целиком найдена в
  тексте резюме и содержит навык как отдельное слово («Java» ≠ «JavaScript»), иначе переносится в
  `unverified_items`.
- 5 задач: `resume_summary`, `job_requirements`, `requirements_check`, `interview_questions`,
  `job_description`. Markdown собирается на сервере из структуры.

## LLM-слой

`OpenAIProvider` — официальный SDK, Chat Completions, `max_completion_tokens`, `response_format:
json_object` для support/hr, `temperature` только если задан. Свои ретраи (SDK `max_retries=0`):
таймаут, сетевые ошибки, 429 (кроме `insufficient_quota`), 5xx; экспоненциальная задержка с
джиттером; общий дедлайн запроса (`REQUEST_TIMEOUT_SECONDS`). Ошибки маппятся в стабильные коды.
Токены берутся из `usage` ответа.

**Почему не OpenAI Agents SDK:** агенты однопроходные, без tools/handoffs; прямой SDK проще,
даёт точный учёт токенов на запуск, детерминированные ретраи и mock-провайдер. Если появятся
агенты с инструментами — Agents SDK можно подключить внутри конкретного `BaseAgent.run`.

`MockProvider` — явный офлайн-режим: детерминированные ответы агентов (support — извлечение
предложений из найденного фрагмента, hr — локальный разбор секций и словаря навыков), баннер
MOCK, `mode: "mock"`, стоимость 0.

## Безопасность

| Мера | Где |
|---|---|
| Аутентификация API-ключом (SHA-256) или JWT маркетплейса; identity не из тела запроса | `security/auth.py`, `security/middleware.py` |
| Изоляция компаний: все выборки по `company_id`; чужой объект → 404 | `services/files.py`, `services/rag.py`, `api/routes.py` |
| Изоляция пользователей: резюме/брифы приватны, база знаний общая в компании | `services/files.py` |
| Rate limiting на пользователя + на неудачные попытки входа по IP | `security/rate_limit.py` |
| Дневной лимит запусков, лимиты расходов (глобальный и на компанию) | `services/quotas.py` |
| Валидация входа (Pydantic, `extra=forbid`, длины), лимит тела запроса | `schemas/`, middleware |
| CORS только из списка, без `*` | `main.py`, `core/config.py` |
| Prompt injection: разделение ролей, нейтрализация разделителей, очистка документов, блокировка override-запросов, правила в промптах, серверная проверка вывода | `security/prompt_guard.py`, `prompts/`, агенты |
| Файлы: проверка сигнатуры и расширения, ZIP-бомбы и коэффициент сжатия DOCX, лимиты страниц/размера, разбор PDF/DOCX в отдельном процессе с таймаутом и лимитом памяти, приватное хранилище 0700/0600, имена файлов не используются в путях | `services/extraction.py`, `services/extract_worker.py`, `services/files.py` |
| Лимит размера тела запроса, в т.ч. без `Content-Length` (chunked) | `security/middleware.py::BodySizeLimitMiddleware` |
| Безопасные ошибки: без stack trace, без эха ввода | `core/errors.py` |
| Логи: только метаданные, редактирование PII/ключей | `core/logging.py`, `core/redaction.py` |
| Заголовки безопасности, строгий CSP демо, `Cache-Control: no-store` | middleware |
| Нет выполнения кода/команд/платежей в агентах; загрузка агентов только из `app.agents.*` | `agents/registry.py` |

## Данные

`agent_runs`: `id, user_id, company_id, agent_slug, agent_version, status, input_tokens,
output_tokens, estimated_cost, execution_time_ms, error_code, created_at` + `language, llm_mode,
model, file_count, source_count`. Тексты запросов/ответов **не сохраняются** (тест проверяет
байты файла БД). Статусы: `running` (выполняется, учитывается в лимитах), `success`, `escalation_required`, `blocked`, `rejected` (ошибка
валидации/лимита до выполнения — не расходует квоту), `error`.

## Ограничения MVP

1. **Реальные вызовы OpenAI не выполнялись в среде разработки** (ключа нет). SDK-интеграция
   проверена через `httpx.MockTransport`; качество ответов на реальной модели нужно оценить вручную,
   особенно казахский язык (рекомендуется ревью носителем).
2. RAG лексический (BM25 + префиксный стемминг): синонимы и перефразирования находятся хуже, чем с
   эмбеддингами. Следующий шаг — гибридный поиск (pgvector + BM25).
3. Защита от prompt injection эвристическая (шаблоны ru/kk/en) + архитектурная; новые формулировки
   атак могут не распознаваться шаблонами — тогда остаются разделение ролей и серверные проверки.
4. HR-маскирование ФИО эвристическое (первая строка/поля «ФИО»); фильтр защищённых характеристик
   консервативный и может давать ложные срабатывания (например, «товары для детей»).
5. OCR не реализован (PDF-сканы → `ocr_required`).
6. Rate limiter in-memory (одна реплика). Квоты и лимиты расходов — по БД: проверка и запись запуска
   атомарны (блокировка в процессе + advisory lock PostgreSQL для нескольких реплик); на SQLite
   несколько процессов-воркеров не поддерживаются — используйте одну реплику или PostgreSQL.
7. Лимит расходов резервирует худший случай (MAX_INPUT_TOKENS + MAX_OUTPUT_TOKENS по тарифам) на время
   запуска; после завершения резерв заменяется фактической стоимостью. Зависший при падении процесса
   запуск со статусом `running` продолжает учитываться в дневной квоте.
8. Нет интеграции с CRM/helpdesk для передачи обращений (handoff только формируется).
9. Синхронная обработка запросов; долгие генерации держат соединение до `REQUEST_TIMEOUT_SECONDS`.
10. Нет стриминга ответов и сохранения истории диалогов на сервере (история передаётся клиентом).
11. Docker-образ собран и запущен в песочнице; `docker compose` с PostgreSQL-профилем не запускался.
